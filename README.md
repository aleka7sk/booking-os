# Booking OS

**Resource-first система бронирований для бизнеса.** Она объединяет заявки из WhatsApp, 2GIS, Instagram, телефона и публичной онлайн-записи в одном календаре, распределяет реальные ресурсы и защищает от двойных броней.


## Что уже работает в MVP

### Для менеджера

- вход по защищённой сессии;
- операционная панель с загрузкой, выручкой, запросами и состоянием ресурсов;
- календарь по конкретным дорожкам, комнатам, залам и другим ресурсам;
- создание брони из WhatsApp, 2GIS, Instagram, телефона, walk-in или вручную;
- автоматический подбор одного или нескольких ресурсов;
- запрос на подтверждение, временное удержание, предоплата и подтверждённая бронь;
- перенос без потери исходного слота при конфликте;
- отмена, завершение и отметка неявки;
- отдельные статусы брони, оплаты и посещения;
- добавление ресурсов и услуг через интерфейс, включая повторяющиеся фиксированные сеансы;
- поиск, фильтры, экспорт броней в CSV;
- неизменяемый журнал значимых действий.

### Для клиента

- мобильная публичная страница без регистрации;
- выбор услуги, даты, количества гостей и продолжительности;
- показ только реально доступных слотов;
- предварительный расчёт стоимости и предоплаты;
- честные режимы: мгновенная бронь, удержание до оплаты или запрос менеджеру;
- фиксация согласия с условиями отмены и персональный публичный статус брони по защищённому токену.


## Доменное ядро

Одна модель покрывает несколько типов бизнеса:

| Сценарий | Пример | Как моделируется |
|---|---|---|
| Эксклюзивный ресурс | Бильярдный стол, корт, фотостудия | Один ресурс целиком занимает одна бронь |
| Несколько ресурсов | 8 гостей требуют 2 дорожки | Количество рассчитывается по вместимости ресурса |
| Общая вместимость | 4 места из 12 на мастер-классе | Несколько броней расходуют capacity одного ресурса |
| Фиксированный сеанс | Мастер-класс по вторникам в 19:00 | Предварительно заданные дни и время |
| Переменная аренда | Студия на 1–5 часов | Минимум, максимум и шаг длительности |
| Буферы | Подготовка 15 минут, уборка 30 минут | Клиентское и фактическое занятое время разделены |
| Подтверждение менеджером | Заявка из приложения | `REQUESTED → HELD → CONFIRMED` |
| Предоплата | 30% в течение 15 минут | Hold истекает и автоматически освобождает ресурс |

Ключевой принцип:

> Услуга — то, что покупает клиент. Ресурс — то, что бизнес обязан зарезервировать для оказания услуги.

## Быстрый запуск

### Вариант 1 — Go

Требуется Go 1.23+.

```bash
git clone https://github.com/aleka7sk/booking-os.git
cd booking-os
go run ./cmd/server
```

Откройте:

- панель бизнеса: `http://localhost:8080`
- публичную запись: `http://localhost:8080/book`

Демонстрационный вход:

```text
owner@booking.local
demo1234
```

### Вариант 2 — Docker Compose

```bash
cp .env.example .env
docker compose up --build
```

Данные сохраняются в volume `booking_data`.

### Настройки окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `BOOKING_OS_ADDR` | `:8080` | адрес HTTP-сервера |
| `BOOKING_OS_DATA_PATH` | `./data/booking-os.json` | файл хранилища MVP |
| `BOOKING_OS_ADMIN_EMAIL` | `owner@booking.local` | первый владелец при создании хранилища |
| `BOOKING_OS_ADMIN_PASSWORD` | `demo1234` | пароль первого владельца |
| `BOOKING_OS_SESSION_SECRET` | development value | HMAC-секрет сессий; обязательно заменить |
| `BOOKING_OS_PUBLIC_URL` | `http://localhost:8080` | публичный адрес инсталляции |

> Email и пароль из окружения применяются только при первом создании файла данных. Для чистого демо удалите `data/booking-os.json`.

## Проверки

```bash
make check       # go test + go vet
make test-race   # конкурентные проверки с race detector
make build       # бинарник bin/booking-os
```

Автоматизированные сценарии проверяют:

- расчёт двух дорожек для восьми гостей;
- price snapshot и депозит;
- переход `REQUESTED → HELD → CONFIRMED`;
- запрет переполнения общей вместимости;
- ровно одного победителя при 20 конкурентных попытках занять последний ресурс;
- атомарный перенос;
- освобождение ресурса после истечения hold;
- запрет поздней оплаты, если истёкший слот уже получил другой клиент;
- обязательную фиксацию согласия клиента с условиями;
- нормализацию расписания фиксированных сеансов и защиту от некорректной конфигурации.

После запуска сервера можно выполнить HTTP smoke test:

```bash
./scripts/smoke.sh http://localhost:8080
```

## Архитектура MVP

```text
Browser / PWA
      ↓
Go HTTP API + embedded frontend
      ↓
Application service / booking invariants
      ↓
Atomic JSON repository
      ↓
booking-os.json
```

Приложение поставляется одним статическим Go-бинарником и не требует npm/CDN во время работы. Frontend встроен через `embed.FS`.

Модули:

```text
internal/domain      сущности и независимые статусы
internal/app         доступность, цена, брони, переходы, аналитика
internal/store       атомарное локальное хранилище и demo seed
internal/security    PBKDF2-HMAC-SHA256 и подписанные сессии
internal/httpapi     REST API, auth и embedded PWA
```

Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Неприкосновенные инварианты

1. `REQUESTED` не занимает ресурс; `HELD` и `CONFIRMED` занимают.
2. Поиск доступности не гарантирует слот — гарантию создаёт атомарная запись брони/hold.
3. Активные allocations не могут превышать эксклюзивность или capacity ресурса.
4. Цена и условия отмены фиксируются внутри брони snapshot-ом.
5. Перенос либо выполняется полностью, либо исходная бронь остаётся без изменений.
6. Отмена и истечение hold освобождают allocations ровно один раз.
7. Оплата не смешивается со статусом брони и посещения.
8. Исторические записи не удаляются молча; значимые действия попадают в audit trail.

## Что является MVP, а не production-версией

Эта версия готова для локального демо и контролируемого пилота одной организации. Для production SaaS следующий обязательный этап:

- PostgreSQL с транзакциями, range/exclusion constraints и миграциями;
- многотенантность и изоляция организаций на уровне БД;
- idempotency keys для внешних API и платежных webhooks;
- официальный платёжный провайдер;
- SMS/WhatsApp/Email-уведомления через outbox/worker;
- восстановление пароля, MFA и управление пользователями;
- резервные копии, observability и rate limiting;
- юридически проверенные согласия и политики хранения данных;
- редактирование настроек, ресурсов и услуг, а не только создание;
- интеграции с CRM, Google Calendar и WhatsApp Business Platform.

Точные границы: [docs/MVP_SCOPE.md](docs/MVP_SCOPE.md). Production-чеклист: [docs/SECURITY.md](docs/SECURITY.md).
